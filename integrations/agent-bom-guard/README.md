# agent-bom guard for Claude Code

A Claude Code plugin with one `PreToolUse` hook on the Bash tool. Before Claude
runs a command, the hook reads the command text, finds the named registry
packages it would install, and checks them. It blocks known-malicious
packages and typosquatted npm and PyPI names, warns about known advisories for
an exact pinned version, pipe-to-shell installs and custom registries, and
prints nothing for clean installs or for commands that install nothing.

```text
/plugin marketplace add koda-ai-studio/agent-bom
/plugin install agent-bom-guard@agent-bom
```

It pairs with the [agent-bom plugin](../claude-code/README.md), which scans what is
already installed; the guard covers the moment a new package arrives.

## What it decides

| Result | When |
|---|---|
| Block (`deny`, Claude is told why) | The package is a confirmed-malicious entry in agent-bom's bundled blocklist and the version is in the affected range (or unpinned); OSV reports it as malware (an OpenSSF `MAL-` report, or a GitHub advisory tagged CWE-506 such as `crossenv` or `event-stream@3.3.6`) and the install is pinned to an affected version or no clean release exists; or the name looks like a typosquat of a popular package, for example `reqeusts` imitating `requests`. The reason names the package it imitates. |
| Warn (the command runs) | An exact pinned version, such as `lodash@4.17.20` or `requests==2.19.0`, has known advisories on OSV; the message lists the IDs by severity. Also used for requirement files (`pip install -r`), which this hook does not open, for a malicious-listed name pinned outside the affected range, for an unpinned install of a package that once shipped a malicious release but has clean ones (`npm install event-stream`), when api.osv.dev cannot be reached, and when a download is piped straight into a shell or interpreter (`curl … \| sh`, `wget -qO- … \| sudo bash`), which runs a script nobody read and no version pins. Also when an install names a custom registry (`--index-url`, `-i`, `--extra-index-url`, `--registry`); the message gives the registry host only, never a user name or token in the URL. |
| Silent | Clean installs, and every command that does not install a named registry package: `npm test`, `npm install` with no names, `pip install -e .`, `echo "pip install x"`, local paths, URLs and git sources. |

Ordinary advisories never block on their own, and an unpinned install ignores them,
because it resolves to the newest release, which is usually fixed. Malware reports are
checked whether or not the install is pinned. The hook never
returns `allow`, so it never skips your own permission prompt.

Recognised installers: npm, pnpm, yarn, bun, npx, pip, pip3, `python -m pip`, uv
(`uv add`, `uv pip install`, `uv tool run`), uvx, pipx, poetry, cargo and `go get` or
`go install`. Commands joined with `&&`, `||`, `;`, pipes or new lines are each
checked, as are `sudo`, `env`, `VAR=value` prefixes and `bash -c '...'`.

## Options

Set these with `/config` or when you enable the plugin (Claude Code 2.1.271 or
later, which supports option lists).

| Option | Default | Effect |
|---|---|---|
| `on_match` | `block` | `block` stops a malicious or typosquat install. `warn` lets it run and shows the finding to you and Claude. |
| `osv_lookup` | `true` | `false` makes every check offline: only the bundled blocklist and typosquat reference are used, and nothing is sent anywhere. |

## Privacy

agent-bom guard runs on your machine and has no account, server or telemetry.
It stores nothing and writes no files. With `osv_lookup` on, the only data that
leaves your machine is the name, ecosystem and pinned version of a package an
install command names, sent to `api.osv.dev`; with it off, every check is
offline. Command text, paths, file contents, environment variables and
credentials are never sent.

### What it runs, reads and sends

- **Runs** `python3 -I ${CLAUDE_PLUGIN_ROOT}/hooks/install_guard.py` once per Bash
  tool call, with a 10-second limit. It needs Python 3.9 or later on `PATH`, uses only
  the standard library, and installs or launches nothing. The command under review is
  parsed as text with `shlex`; it is never executed, expanded or evaluated.
- **Reads** the hook event from stdin and `hooks/guard_data.json`, a small snapshot
  of agent-bom's typosquat reference and confirmed-malicious blocklist generated by
  `scripts/generate_guard_data.py` in this repository. It reads no other files and
  no credentials.
- **Sends**, only when `osv_lookup` is on and the command installs a named package,
  each package's name, ecosystem and version (when pinned) to `api.osv.dev`: one
  `POST /v1/querybatch`, then up to six `GET /v1/vulns/<id>` requests for advisory
  severity and malware tags (malware reports are fetched first). Each request times out after 2 to 3 seconds. Nothing else leaves the
  machine: no command text, paths, file contents, environment or telemetry.
- **Stores** nothing and writes no files.

## When something goes wrong

The hook fails open. If it hits an internal error it lets the command run and shows
`agent-bom-guard: internal error (...); this command was not checked`. Malformed
hook input is ignored silently. If `python3` is missing (common on Windows), Claude
Code reports a non-blocking hook error and the command runs unchecked. If OSV is
unreachable, the offline checks still run and a short note says so.

## Limits

- Only package names written in the command are checked. Requirement files,
  lockfiles, manifests and transitive dependencies are not; run `/agent-bom:scan`
  for those.
- Typosquat detection compares names against about 300 popular npm and PyPI packages
  each, taken from public download and dependent rankings plus documented campaign
  targets (`src/agent_bom/data/popular_packages.json`; how it is built is in
  `scripts/generate_popular_packages.py`). Ranked projects that sit next to a popular
  name, such as `psycopg2`, are never flagged. It is still a heuristic: on held-out
  less-popular packages about 0.3% (npm) and 0.4% (PyPI) of names were flagged, so a
  genuine package with a lookalike name can be blocked. Use `on_match: warn`, or run that install yourself, and report the name so
  it can join the verified list.
- Commands built at run time (`pip install $(cat list)`) cannot be read and are not
  checked.

## For directory reviewers

This plugin lives in a subfolder of its repository and its hook runs a Python file,
so the directory validator reports **Scripts the validator couldn't follow** and
holds it for a reviewer. A shell wrapper would be held for the same reason, because
it would run another file, so the hook calls the Python file directly in exec form.
The two files it runs are `hooks/install_guard.py` and `hooks/command_parser.py`.
Neither starts processes, installs packages or uses launchers. `tests/test_agent_bom_guard.py`
in the repository covers the parser, the decisions, the data snapshot and the hook
contract.

To try a local checkout: `claude --plugin-dir integrations/agent-bom-guard`, and
`claude plugin validate integrations/agent-bom-guard --strict` before publishing
changes.

### Performance
- The PostgreSQL current-graph row copy runs in a child process, so it no longer holds the API's Python interpreter lock while it streams a large estate beside graph reads. Guards, promotion and the fallback rebuild stay in the API. The child reads its database connection from the environment it inherits (never its command line), reports only an error's type, and is killed after 10 minutes, on API exit, or when the API that started it is gone; any outcome other than a committed copy falls back to the in-process rebuild, and a child that dies mid-copy leaves nothing to promote.

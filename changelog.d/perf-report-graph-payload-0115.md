### Upgrade notes
- `scan -f json` now writes report schema 2.0 (`schema_version: "2.0"`, contract in `contracts/v2/`). Each compliance control, package, asset and provenance record is written once and referenced by ID: `findings[].controls` becomes `findings[].control_refs` into a top-level `compliance_controls` map, package occurrences carry `package_ref`, finding assets `asset_ref`, blast-radius rows `finding_ref`, provenance objects `*_provenance_ref` into `provenance`, and the root `packages` alias and `inventory_snapshot.packages` are omitted. `packing.transforms` lists the rewrites. `agent_bom.output.report_packing.expand_report` restores the 1.0 document exactly, and every agent-bom reader (report commands, `--baseline`, `--inventory`, `graph`, `mesh`, `attest`, `findings push`, MCP tools, the dashboard import) does so on read. A script that reads the JSON report directly should expand it the same way, or run the scan with `--report-format legacy` (or `AGENT_BOM_REPORT_FORMAT=legacy`) to keep writing 1.0. The GitHub Action keeps writing 1.0 for its own steps and downstream workflow steps.
- `scan --push-url` sends 2.0 only to a control plane whose `GET /version` lists `"2.0"` in the new `report_schema_versions` field, so a 0.115.0 client keeps working with an older control plane, and an older client keeps working with a 0.115.0 control plane. `POST /v1/results/push` expands a 2.0 report before validating and storing it: stored results, findings and graphs are the same for either version. A 2.0 push with a reference that names no record is refused with 422, and one whose references would expand past the 240 MiB storage ceiling with 413.
- The Python API (`to_json`, `to_redacted_json`, `export_json`, `write_redacted_json`) keeps returning 1.0 unless called with `report_format="v2"`.

### Performance
- The JSON scan report is about a third smaller with the same evidence: 6.26 MB to 4.15 MB for a 10-package project with 176 CVE findings, and 21.7 MB to 12.9 MB for this repository with `--quick` (1.5x and 1.7x; compact push bodies shrink about 1.5x). Findings, controls per finding and entity data expanded from 2.0 equal the 1.0 report exactly.

### Fixed
- Go binaries built with Go 1.17 or older report their Go release and modules. Their build info holds pointers rather than inline strings, and those are now resolved through the ELF, Mach-O or PE segment table; when that fails, the binary is searched for the module list and a single unambiguous `go1.x` release. A Go binary whose release still cannot be read is recorded as a coverage gap (`prom/node-exporter:v1.3.0` went from 0 packages to `stdlib` 1.17.3 plus 42 modules).
- `agent-bom image --tar` no longer exits 0 when the archive yields no packages and no model files: that is reported as an extraction failure and the image-only scan exits 1, as an image reference already did.
- Model references keep the full vendor ID: `claude-sonnet-4-5` and `gpt-4.1` are no longer shortened to `claude-sonnet-4` and `gpt-4`. Current families are recognised, including `gpt-5`, `gpt-6.1-sol`, `gpt-oss`, the o-series (`o1`, `o3-pro`, `o4-mini`), `gemini-3.1-pro-preview`, and `claude-opus-5-5`, `claude-fable-5-2` and other `claude-<line>-<version>` IDs. Trailing parts are limited to known variant words and numbers, so prose such as "a gpt-5-based agent" is not reported as a model.
- A skill whose review verdict is `high_risk` (such as shell access) has status `suspicious`, not `malicious`; `malicious` now requires a blocked finding or malicious content. The UI contract and demo data use the review verdict `trusted` that scans emit, instead of `clean`.

### Fixed
- The findings "Affected asset" cell names the first two agents and then "+N more", counted from every affected agent, linking to the advisory's affected view (or the finding drawer for non-advisory findings); agents are list items, so a wrapped line never starts with a comma. The phone card names the remainder the same way.
- The "Prioritize fixes" header states the cap against the snapshot's path total, for example "1,133 candidates · 5,000 of 7,005 paths assessed · capped", with grouped numbers throughout. The remediation priorities payload carries `total_paths` (distinct recorded paths).
- A finding whose graph reachability was never assessed because the snapshot's path search stopped at a budget (for example the holder-chain budget) now shows "Not assessed (budget)" in the reach cell instead of a blank, and "Not assessed (refreshing)" while the current graph is being prepared. The findings API and MCP finding summaries carry `graph_reachability_not_assessed_reason` (`path_budget` or `graph_refreshing`); the field is server-stamped and stripped from stored or imported rows.
- `scan -q --exit-zero` no longer reports PASS when the default high gate matched: the verdict reads `FAIL (exit forced to 0 by --exit-zero)` with the finding that failed it, and the `-q --log-json` verdict record is `WARNING` with `verdict: FAIL`, `exit_code: 0` and `exit_forced_by: --exit-zero`.
- `agent-bom skills scan` tables name each row by skill (the directory of `SKILL.md`, else the file name, with the path only when two names collide) and fit every column in an 80-column terminal, so a malicious skill is identifiable instead of a truncated common path prefix.
- Graph accessible names and tooltips built from node ids decode percent-encoded segments ("agent:Team 5 Agent 32", not "Team%205%20Agent%2032") across the rollup surface, search results, impact groups, exposure summary, path explanations and the overview neighbor list.

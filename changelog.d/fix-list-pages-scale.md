### Changed
- The Agents page holds up at thousands of agents: `GET /v1/agents` accepts `limit` (up to 500), `offset` or `cursor`, `q` (name, type, source or id), repeatable `type`, `status` and `source` filters, and `sort`/`order` on name, servers, packages, credentials or vulnerabilities, and returns `total`, `next_cursor`, per-filter `facets` and a population `summary`. The page pages, sorts and filters on the server, keeps its state in the URL, and its tiles count every agent rather than the visible page. Search now matches agent type as its placeholder said. Calls without these parameters still get the full list.
- Agent counts no longer read as contradictory: the Agents page tile names its own population (scanned agents or agents on this host) and shows the Overview number beside it as "agent records in snapshot", and the Overview tile explains that it counts every graph agent record, including cloud-managed agents.
- The MCP Catalog asks for one page at a time instead of downloading the whole registry: `GET /v1/registry` accepts `limit`, `offset` or `cursor`, `q`, and repeatable `risk` and `category` filters, and returns `total`, `facets` and whole-catalog `risk_counts`.

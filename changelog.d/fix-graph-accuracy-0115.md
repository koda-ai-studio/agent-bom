### Fixed
- The grouped full map marks attack paths again on scanned estates. Scans store their paths only in the snapshot path index, but the map read an older table that scans leave empty, so every group showed zero nodes on an attack path while `GET /v1/graph/attack-paths` listed them. The map now reads the same stored paths as that endpoint on SQLite and Postgres, and falls back to the older table only for snapshots that have nothing in the index. Node paths (`GET /v1/graph/paths`), graph queries with `include_attack_paths` and AI explanations read the same paths.
- Every other per-snapshot attack-path reader now reads the stored path index too, so on scanned estates findings on an attack path are marked `graph_reachable`, `GET /v1/graph/diff` counts new attack paths, scenario comparisons report the snapshot's paths, impact depth follows the longest stored path, and attack-path delta alerts fire for routes the previous scan did not have. Before, all of these read a table scans leave empty and saw no paths.
- A grouped full map that fails to load falls back to the ungrouped map without recording that the reader turned grouping off. It no longer adds a "Group the map" row the reader never asked for, and a reload tries the grouped map again.
- "Fit all" and every canvas fit button keep card text at 11px or more on screen. A graph too large for that is framed at the legible scale and panned, instead of being shrunk until labels drew at about 5px. This covers the investigation graph, the attack-path and agent architecture canvases, the grouped map, the scope preview and the agent topology. Phone attack-path canvases and the architecture canvas now stop at the scale where 15px names stay at 11px, and the finding count on compact cards scales with the rest of the card. The in-view note says to drag for the rest instead of promising that Fit all shows everything. A non-interactive capture (`capture=1`) still frames the whole graph, since it cannot be panned.
- Package counts name what they count. The Agents page shows "Package references" (one per agent that declares a package), while Overview and Asset inventory show "Unique packages" in the snapshot, so 1,314 and 1,137 for the same snapshot no longer read as a contradiction.
- The posture summary lists severities critical first: "2 critical · 19 high · 24 medium" instead of ordering them by how much each moved the grade.
- Agent identifiers such as `project:agent-a1157…`, ARNs, URIs and hash-bearing ids render exactly as recorded instead of being title-cased, in the API's `display_name` and in the UI. Credential references keep their exact environment-variable names.

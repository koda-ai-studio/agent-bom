### Fixed
- `agent-bom secrets` and the runtime gateway no longer report plain numbers as phone or card numbers. Card matches must pass the Luhn checksum; phone and card matches touching a decimal point, an exponent, a longer digit run or a dashed id (a UUID) are rejected; and in the file scanner a bare digit run needs a phone or card field name. Floats, epoch timestamps, limits and byte counts in JSON and YAML stop reporting (this repository: 21 phone and 5 card findings to 0), while formatted phone numbers and Luhn-valid cards are still found, redacted and alerted on.
- A route's 503 raised from a storage outage (a locked SQLite file, an unreachable PostgreSQL) now carries `Retry-After` and logs the storage error class, sanitized message and correlation id, matching an unhandled storage error. `POST /v1/results/push` hitting a locked store answers the retryable envelope.
- API failure logs name the exception class and its sanitized message instead of only "An internal error occurred".
- `agent-bom skills scan` and other CLI commands no longer print the server warning about `AGENT_BOM_AUDIT_HMAC_KEY` when a durable database is configured; the API server still warns at startup.
- The `agent-bom skills scan` Instruction Surface table keeps every column whole at 80 columns, including the widest values; the review column is named Action and the findings column Find., with a one-line legend.
- Finding and graph tooltips built from node ids show decoded ids ("project:pom", not "project%3Apom"): the findings reach badge and affected-asset holder, changed attack path endpoints, and control evidence path rows.
